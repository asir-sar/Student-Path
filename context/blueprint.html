Not fine-tuning the LLM. Knowledge injected by training is unreliable, carries no citations and goes stale with the next catalogue.

Not full GraphRAG. The relationships (groups, recommended skills, lecturers) are few and explicit, so they are extracted deterministically.

Not free-form text-to-SQL. Typed read-only tools are safer and testable. A guarded version stays as a stretch goal.

Work with AI like a senior engineer: checks first, core code yours

The loop for every task

  1. Write the check first: a test, an eval case or a metric gate.
  2. Ask the assistant for a plan, not code, and critique it against real data samples.
  3. Write the learning-critical core yourself; delegate the scaffolding.
  4. Run the tests and evals, and read the failures, not only the score.
  5. Have the assistant review your diff; review every line it wrote.
  6. Log the decision and the numbers in DEVELOPMENT_LOG.md.

Keep a short CLAUDE.md (commands, layout, conventions, a "never" list) and your context/ docs current. Start each session from the plan section you are working on.
